# All Hub / Эйра — запуск и проверка (Android + Windows)

Этот документ описывает **текущий** способ подключения локальных сервисов и проверки поставки. Наличие кнопки или успешный CI не доказывает, что установка/обновление проверены на конкретном устройстве.

## 1. Установка All Hub

1. Откройте [Releases](https://github.com/PerchikHot/all-hub/releases), а не список коммитов или временных GitHub Actions artifacts.
2. Выберите релиз, в котором **одновременно** присутствуют Android APK и Windows portable ZIP. Проверьте номер версии и дату релиза.
3. Android: скачайте APK на телефон и подтвердите установку в системном установщике. Обновление поверх существующей версии возможно только при совпадении package ID и сертификата подписи; при несовпадении **не удаляйте** установленную версию без резервной копии.
4. Windows: распакуйте **весь** portable ZIP в отдельную папку, не запускайте EXE прямо из архива. Не удаляйте пользовательские данные при замене версии.
5. Во вкладке «Проекты» проверьте «установлена / доступна» и кнопку «Обновить». При обновлении Android требуется системное подтверждение. Для Windows передача установки отдельному процессу и перезапуск должны проверяться на реальной машине.
6. Если новая версия не обнаружена, убедитесь, что опубликован GitHub Release с нужными файлами; успешная сборка Actions сама по себе не создаёт доступного обновления.

## 2. Ollama: чат Эйры

1. Установите Ollama на компьютер, запустите сервис и заранее загрузите совместимую чат-модель. Проверьте работу модели непосредственно в Ollama.
2. Откройте All Hub → «ИИ» → Ollama/Эйра. Для **Windows на том же компьютере** исходный адрес — `http://127.0.0.1:11434`.
3. Для **Android, подключённого к Ollama на ПК**, `127.0.0.1` означает **сам телефон**, а не компьютер. Укажите локальный IP компьютера и порт 11434. Сервис должен слушать доступный сетевой интерфейс; проверьте правила брандмауэра и что оба устройства находятся в доверенной сети.
4. Не открывайте Ollama в публичный интернет без отдельной защищённой прокси/аутентификации. Удалённый сервер может получать текст запросов; доступ к личной памяти требует отдельного разрешения для конкретного адреса.
5. Выберите доступную модель и отправьте тестовую реплику по-русски. Русскоязычная инструкция персонажа **не является дообучением** и не гарантирует соблюдения характера любой моделью.

## 3. Локальный GGUF на Android

1. На вкладке «ИИ» импортируйте GGUF через выбор файла. Не путайте импорт файла с доказательством возможности генерации.
2. Дождитесь завершения копирования и проверки целостности. Убедитесь, что хватает постоянной памяти и ОЗУ; на слабых телефонах используйте небольшие квантованные модели.
3. Выберите модель и выполните проверку загрузки/контекста. Затем откройте GGUF-чат и отправьте короткую фразу.
4. Если модель не загрузилась, проверьте свободную ОЗУ, архитектуру ARM64, совместимость GGUF с собранной версией llama.cpp и доступность нативных библиотек. Проверка контекста сама по себе не подтверждает корректность генерации.
5. Экспорт/импорт **текстовой** переписки между GGUF и Ollama выполняйте вручную через JSON. Вложения, локальные пути к моделям и изображения этим переносом не передаются.

## 4. Forge API: генерация и редактирование изображений

1. Запустите Stable Diffusion WebUI Forge на ПК с включённым `--api` и загруженной моделью.
2. Откройте All Hub → «ИИ» → Forge. Для Windows на этом ПК начальный адрес — `http://127.0.0.1:7860`; для Android нужен доступный IP компьютера с портом 7860.
3. Обновите список моделей, выберите checkpoint, введите запрос и выполните генерацию. Для img2img выберите PNG/JPEG до 12 МиБ и задайте силу изменения.
4. Результат сначала находится в памяти приложения: нажмите сохранение и выберите место. Закрытие экрана до сохранения может привести к потере результата.
5. Не публикуйте Forge API в интернет без защиты. Передача фотографии на сервер за пределами устройства раскрывает её этому серверу; проверяйте адрес до отправки.

## 5. Память, резервные копии и приватность

- Переносимый снимок памяти Эйры — JSON формата `all-hub-eyra-memory`, версия 1. Он содержит характер, заметки и выдержки; **не содержит** учётные данные, разрешения устройства или адреса серверов.
- Импорт памяти ограничен размером и количеством записей. Создайте резервную копию перед объединением или заменой. Снимок памяти и экспорт переписки — **разные** форматы.
- Не загружайте экспорты ChatGPT, переписки, фото, токены и персональные архивы в публичные issues/PR/репозиторий. Импорт выполняйте локально через интерфейс приложения.
- Доступ к файлам, уведомлениям, устройствам и удалённым сервисам предоставляйте только по необходимости; системные разрешения не подменяются разрешением в интерфейсе.
- Автоматическая синхронизация памяти между устройствами и автономное управление ПК **не должны считаться готовыми**, пока соответствующие сценарии не проверены отдельно.

## 6. Матрица приёмки релиза

| Проверка | Условие принятия |
| --- | --- |
| Android CI | `flutter analyze`, `flutter test`, подписанный APK, проверка пакета и опубликованный артефакт завершены успешно |
| Windows CI | `flutter analyze`, `flutter test`, `flutter build windows --release`, полный portable ZIP опубликованы |
| Обновление Android | APK версии N+1 устанавливается поверх N с сохранением данных и системным подтверждением |
| Обновление Windows | EXE версии N+1 заменяет N после закрытия приложения, перезапускается и сохраняет данные |
| Ollama | Русский запрос → ответ модели; недоступный сервер → понятная ошибка и повторная попытка |
| GGUF | Импорт → выбор → загрузка → реальная генерация → восстановление переписки после перезапуска |
| Forge | Список моделей → txt2img → сохранение; img2img → сохранение; ошибки соединения видны |
| Память | Экспорт → перенос на второе устройство → импорт → проверка записей; удаление и отзыв разрешений |
| Приватность | Никаких приватных данных в репозитории, логах CI и публичных артефактах |

Проверка на физическом Android и Windows обязательна дополнительно к GitHub Actions. Если хотя бы один из пунктов не подтверждён, не обозначайте его как готовый.
